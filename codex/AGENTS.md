# 공통 Codex 에이전트 정책

- `rg`와 범위가 좁은 파일 읽기를 우선하고, 큰 테스트·빌드·로그·diff에만 `rtk`를 사용한다.
- 실질적인 작업은 목적에 맞는 역할 한 명에게 위임하는 것을 기본으로 한다. 총괄은 범위 설정·조정·결과 검증·종합을 맡고 위임한 조사나 구현을 중복하지 않는다. 단계가 바뀌면 검증자·검수자에게 순차 인계하며, 동시에 역할을 추가하는 것은 독립적인 읽기 작업이 있을 때뿐이다.
- 총괄은 목적, 허용 경로, 금지 경로, 완료 조건, 검증 명령과 소유권을 먼저 정한다. 구조적 개발 작업은 task card와 API/data contract를 준비하고, 단순 사실 확인과 작은 편집에는 문서를 강제하지 않는다.
- 공유 작업공간에서는 한 번에 writer 한 명만 수정한다. 총괄의 계약·문서 수정도 writer로 센다. 독립적인 읽기만 병렬화하며, 위임 깊이는 1단계로 제한한다.
- 구현자와 실행 검증자, 독립 검수자를 구분한다. 검수자는 실제 diff와 실행 근거를 확인하고 제품 파일을 고치지 않는다. 실행 결과와 명세 판정은 각각 기록한다.
- 같은 원인의 수정이 두 번 실패하면 Luna 역할에서 Sol 역할로, 이후 Astra 전문 역할로 승격한다. 자동 무한 재시도는 하지 않는다.
- 범용 설정·문서·빌드 스크립트는 총괄이 writer 소유권을 인수할 수 있으며, 수정 뒤 독립 검수를 받는다.
- 각 역할 TOML의 모델·추론 설정을 따른다. 성능 향상률은 실제 파일럿으로 확인하기 전에는 주장하지 않는다.
- 새 역할은 하위 에이전트를 만들거나 재위임하지 않는다. 필요한 스킬은 부모 총괄이 먼저 읽고, 목적·범위·소유권·필수 근거를 포함해 위임한다.
